# AI Resume Builder — Full Product Ideation

## 1. Conversational Resume Builder
- Section by section guided conversation — Personal Info → Work History → Skills → Education → Tailor & Polish → Export
- AI interviews the user per section, asks follow up questions if answers are thin
- If user seems stuck, offer examples
- Raw user input transformed into polished impact driven bullet points
- e.g. "I worked on ML models" → "Developed production ML pipelines that reduced customer churn by 22%"
- Live resume preview updating in real time as sections are completed
- Resume strength indicator showing completion percentage

---

## 2. Base Resume — Single Source of Truth
- User builds base resume once — every job, every skill, every project, full history
- Never deleted from, only grows over time
- Never shown directly to employers
- All tailored resumes and cover letters derived from it
- Self rated skill level stored alongside assessed skill level separately

---

## 3. Job Post Ingestion
- User inputs a LinkedIn / Naukri / Monster job post URL
- Scrape the JD automatically using Jsoup or equivalent
- Graceful fallback — if scraping blocked, prompt user to paste raw JD text
- Parse and structure the JD for analysis

---

## 4. Job Fit Analysis
- Match base resume against parsed JD
- Generate a fit score
- Surface what's strong, what's weak, what's missing
- Output format:
  - Strong matches highlighted
  - Partial overlaps surfaced — e.g. Docker counts toward Kubernetes gap
  - Missing keywords and skills clearly listed
  - Significance of each gap rated

---

## 5. Skill Gap Analysis
- Identify skills in JD not present or weak in base resume
- Rate severity of each gap
- Feed directly into learning roadmap
- Semantic matching — "stakeholder management" matches "client communication", "ReactJS" matches "React.js"
- Use embeddings in v2 for smarter semantic matching

---

## 6. Tailored Resume
- Derived from base resume, never replaces it
- Reorders and rewords bullet points to match JD language
- Emphasises relevant experience, de-emphasises irrelevant
- Keywords matched for ATS compatibility
- Process of building is honest and internal
- Output is always polished and positive — brutal tone never appears in exported resume
- User can iterate until satisfied

---

## 7. Structured Elicitation Before Tailoring
- Instead of open ended chat, present 5 targeted questions upfront
- Questions dynamically generated by a small cheap LLM call reading the JD
- Asks most relevant things — leadership role asks about management style, technical role asks about specific project experience
- User answers all 5, then single rich LLM call made with everything baked in
- Controls API costs without sacrificing quality
- UI framing — "Answer these questions so we can tailor your resume in one shot"
- One rich prompt, one LLM call, one generation

---

## 8. Cover Letter Generator
- Personalized to the specific role
- Captures user personality, interests, work style, what they value in a team
- What excites them about the role
- Always professional and warm regardless of tone setting
- Tone setting never applies to cover letter — it is outward facing
- Differentiator — feels human, not generic

---

## 9. Skill Assessment
- Triggered after gap analysis — "want to check how much you already know?"
- Also works proactively — verify self rated skills on base resume
- Adaptive 5-10 questions per topic, generated by LLM on the fly
- No static question bank needed
- Mix of MCQ for recall and scenario questions for depth
- Difficulty adjusts based on answers — confident answers ramp up difficulty, struggling pulls back
- Mimics how a real interviewer probes
- Result levels — Beginner / Familiar / Proficient / Expert
- Feedback — not just a score but why, with specific things to work on
- e.g. "Strong on theory, weak on practical application"
- Self rated level vs assessed level stored separately in base resume
- Framed as approximate self calibration, not a certification

---

## 10. Learning Roadmap
- Generated per skill gap
- Tied to assessment results — if assessed as Familiar, roadmap starts from there not zero
- What to study and in what order
- Topics to cover to close each specific gap

---

## 11. Tone Setting
- Applies only to inward facing features:
  - Skill assessment feedback
  - Fit analysis
  - Gap analysis
  - Resume building conversation
- Never applies to:
  - Cover letter — always warm and professional
  - Exported resume — always polished
- Slider UI — drag to preferred tone
- Levels — Encouraging → Balanced → Honest → Blunt → Brutal
- Mentor mode — honest + explains why each gap matters to a hiring manager and what it signals
- Preview of tone shown when slider moved — sample feedback rendered in that tone
- Soft confirmation gate at brutal end — "this feedback will be direct and unfiltered, are you ready?"
- Saved as user preference across sessions — personality preference not session setting
- Technically just a system prompt variable — no extra LLM cost

---

## 12. ATS Score
- Simulates how an Applicant Tracking System parses and ranks the resume
- Checks:
  - Keyword match — does resume contain exact JD terms
  - Keyword density — natural usage vs stuffed
  - Section detection — can ATS find Experience, Education, Skills clearly
  - Formatting safety — no tables, columns, graphics that confuse parsers
  - File format compatibility note
- Output — score out of 100 with specific pass/fail/warning per check
- Template choice surfaced here — single column templates score higher, warn user at template selection
- Shown before export so user can iterate

---

## 13. Recruiter View Score
- Simulates how a human recruiter skims in 6-8 seconds
- Different from ATS — pattern matching not keyword parsing
- Checks:
  - Career trajectory — does it make sense, show growth
  - Company name recognition
  - Title progression
  - Summary compelling at a glance
  - Anything that raises a flag
  - Employment gaps — surfaces them with suggestion to address in cover letter
  - Quantified impact — flags roles with no numbers
- Output — score with specific observations and suggestions
- Both ATS and Recruiter scores shown before export
- User iterates until both are green, then exports

---

## 14. LaTeX Template System
- 4-5 curated templates built in house — no Overleaf licensing concerns
- Templates:
  - Minimal — single column, whitespace, good for designers and writers
  - Modern — two column, subtle color accent, good for tech roles
  - Classic — traditional conservative, good for finance law corporate
  - Academic — dense, publication friendly, good for research and PhD
  - Creative — bold header, unique layout, good for marketing and product
- LaTeX source files with placeholders, populated via string interpolation at generation time
- Compiled via pdflatex running in Docker — isolated as separate microservice
- Template choice linked to ATS score — warn user if choosing two column layout
- PDF exported and served for download

---

## 15. Application Tracker
- Every job targeted stored as an Application record
- Contains: job post URL, parsed JD, fit score, skill gaps, learning roadmap, tailored resume, cover letter, ATS score, recruiter score
- User can see history of every role targeted
- Becomes a personal job tracker over time

---

## 16. Embeddings — V2
- Semantic skill matching — React vs ReactJS, stakeholder management vs client communication
- JD to resume cosine similarity for smarter fit scoring
- Partial overlap detection — Docker counts toward Kubernetes gap
- Skip in v1, use LLM for semantic heavy lifting initially
- Keep data model open to adding embeddings later

---

## Tech Stack
- Frontend — React with Vite
- Backend — Python FastAPI
- Agent orchestration — LangGraph for stateful flows and decision trees
- LLM — Ollama locally to start, swap to Gemini / OpenAI / Anthropic via abstraction layer
- ORM — SQLAlchemy + Alembic for migrations
- PDF generation — LaTeX templates + pdflatex in Docker container
- Task queue — Celery + Redis for heavy background jobs
- Dependency management — Poetry
- Testing — Pytest

Personal Projects

User adds personal projects to their base resume
Fields:

Project name
Description
Tech stack used
Your role
GitHub URL / live demo URL / portfolio link
Impact or outcome if any — stars, users, contributions


GitHub URL handling:

Fetch repo metadata automatically — readme, language, star count, fork count, last active
Use that to enrich the project description rather than asking the user to retype what's already in the readme
If repo is private, fall back to manual description


AI enrichment:

Raw description rewritten into impact driven project summary
Tech stack extracted and cross referenced with skills section — auto suggests adding missing skills to base resume
e.g. user has a LangGraph project on GitHub but never listed LangGraph as a skill


Showcasing logic:

Not every project included in every tailored resume
Fit analysis decides which projects are most relevant to the JD
Relevant projects surfaced and highlighted, others de-emphasised
Same base, tailored view — consistent with the rest of the product
